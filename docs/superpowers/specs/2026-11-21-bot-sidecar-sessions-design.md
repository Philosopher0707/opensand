# Design: bot sidecar with per-bot sessions & identity

Date: 2026-11-21
Status: approved by owner (visual companion — layout A + identity editor mockups)
Reference parity target: OpenMausBot `BotModelBadge`, `SidebarBotTile`, `ModelPicker`, `Avatar` (see `docs/agent-delegation-communication-map.md`)

## Goal
The sidecar lists every bot as a compact card. Each bot owns its own session; clicking a card opens that bot's session in the main pane. Delegated work must appear in the **delegated bot's** session (not only as a nested card in the parent). Every bot has a custom inline-SVG icon with owner-picked color/expression, editable from the card.

## Non-goals
- No new dependency (icons are inline SVG, colors are hex strings).
- No git worktrees, no bots-in-separate-OS-processes (agents remain in-process coordinators).
- No full `models.dev` catalog clone; reuse existing `/api/providers` + `/api/models`.
- No mascot eye-tracking animation (static SVG shapes + expression states only).

## Architecture

### 1. Session identity (data)
- A bot's home session is `bot_<agentId>` (deterministic), persisted like any other session via `SessionMetadata`/`event-log.jsonl`. Validated: agent ids are `agent_<slug>_<hex>` (`agent-store.ts:211-212`) and `/^[a-zA-Z0-9_-]+$/` (`desktop-server.ts:386`, `ipc-bridge.ts:1184`) accepts `bot_agent_foo_ab12cd34`.
- Delegation already creates `sub_<agentId>_<ts>` child sessions. Map them to the target bot: on `subagent` event, derive `subagent.agentId` (`shared/src/types.ts:401-411`, set at `orchestrator-tools.ts:500-508`) → the owning bot's home session.
- **One authoritative rendering destination per event:** child turn content is rendered ONLY in the target bot's home-session buffer (or its nested card when that bot is open). The parent receives a compact "delegated → Bot" reference line only; no full child text. This avoids double rendering.
- Empty-session load is already tolerated: `bridge.loadSession` returns `{events:[], transcript:''}` for a missing session (`ipc-bridge.ts:1178-1225`) and the HTTP route always writes 200 (`desktop-server.ts:535-546`). A brand-new `bot_<id>` has no `meta.json`, so the card click MUST set `activeAgentId` itself and then call `selectSession` (current `refreshBots` click does neither).
- No schema change to `SendTurnInput`; renderer passes `sessionId` = bot home session + `agentId` = bot id.

### 2. Sidecar cards (renderer)
- Replace `refreshBots()` DOM with `bot-rail-card` rows: SVG avatar (from `logoSvg`/`logoColor`, initial fallback), name, provider·model badge (`provider || 'global'` · `model || 'default'`), status dot (`data-status` = idle/active/busy), hover actions: identity (🎨), model picker, delete.
- Click card → open bot home session in main pane (`selectSession` with `bot_<id>`, set `activeAgentId`).
- Default Assistant row stays first (no agent id, global session).

### 3. Identity editor (renderer module)
- Render boundary: `botAvatarMarkup` accepts ONLY the exact SVG templates generated by `bot-identity.js` (identified by a `data-icon` key) or an initial tile; any other/unknown `logoSvg` value (legacy or hostile, e.g. `<svg onload=...>`) falls back to the initial tile. Never inject raw stored SVG into `innerHTML`. Name/role/id always go through `escapeHtml`. Expression applies only to the mascot shape.
- `renderer/modules/bot-identity.js`: `openBotIdentity({bot, anchor, onSave})` → popover with:
  - 5 icon shapes (mascot, diamond, gear, spark, orb) as inline SVG templates
  - 6 accent colors (blue, purple, green, amber, red, slate)
  - 3 expressions (neutral, happy, focused) for mascot shape
  - Live preview; Save calls `client.updateAgentSettings(id, {logoSvg, logoColor})` then `refreshBots()`.
- SVG is sanitized at generation time (module produces fixed templates only); rendered with `innerHTML` from our own constant, never from user text.

### 4. Delegation → delegated bot session
- **Filter bypass (critical):** `ipc-bridge.ts:737-749` tags subagent events with the PARENT `sessionId`, and `app.js:5244-5246` returns early for events whose `sessionId !== currentSessionId` BEFORE the subagent branch at `:5249`. Handle `event.type === 'subagent'` by `event.subagent.agentId` BEFORE that filter, otherwise delegated work is silently dropped whenever the delegated bot's session is open.
- **New infrastructure (not a reuse):** there is no per-session message buffer map today (`app.js:4023,4050` only attaches `_subagentCards` to the single `currentAssistantMessage`; `parallel-board.js` has a DOM pane Map). Introduce `renderer/modules/session-buffers.js` with `Map<sessionId, messages[]>`, a `append(sessionId, message)` writer and `renderInto(sessionId, feedEl)` reader called by `selectSession` (`app.js:4328-4360`). The Parallel Board keeps its own pane Map; both write through this shared buffer.
- Badge lifecycle: mark the card of `event.subagent.agentId` (NOT `activeAgentId`, which `app.js:5226,5228` currently uses) with "delegated work" + unread dot; clear the unread dot when that bot's session is opened.

### 5. Error handling
- Unknown provider/model falls back to "global"/"default" labels.
- If `logoSvg` is malformed (legacy data), fall back to initial tile; never throw.
- Delete requires `confirm()` in UI (helper tool already requires `confirm=true`).

## Testing
- Real-Electron window-harness: seed 2 agents with `logoSvg`/`logoColor`; assert 2 `bot-rail-card` rows, SVG present, color applied, name escaped, clicking a card sets `activeAgentId` AND switches `currentSessionId` to `bot_<id>` even with no transcript on disk. Identity editor change must survive an IPC round-trip/reload, not just a re-render.
- Security: inject a hostile `logoSvg` (`<svg onload=...>`) via a seeded record; assert the card renders the initial-tile fallback and no `onload` attribute exists in DOM.
- Delegation routing: inject a synthetic `subagent` event for CTO Bot while the PARENT pane is open; assert it lands in CTO Bot's buffer only (no child text in parent), the target card gets the unread badge, and no cross-session leakage. Open CTO Bot's session and assert unread clears.
- Full hermetic gate + live screenshot via `scripts/capture-ui.sh`.

## Risks
- Session id charset: `bot_` + `agent_<slug>_<hex>` contains underscores only — allowed by current `isValidId`.
- `client.sendQuery(q, sessionId, agentId)` is positional (`app.js:5077` → `ipc-bridge.ts:798-802`); `SendTurnInput` itself carries `threadId`/`botId`, so no change there — the renderer simply passes the bot's session id and agent id as the existing positional args. A brand-new bot session loads as empty (200 with empty events), not a 404; the card click sets `activeAgentId` and calls `selectSession`.
- Identity SVG stored inline could grow records; fixed small templates keep it bounded (<1KB).
