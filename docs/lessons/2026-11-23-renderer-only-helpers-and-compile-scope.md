# Renderer-only helpers trip the dead-export gate, and renderer types live outside the desktop build

- **Trap:** Adding pure helpers to `packages/desktop/src/shell/composer-model.ts` for the Preact renderer made `scripts/check-dead-exports.sh` fail with four "exported but not imported" findings, even though `Chat.tsx` imported all of them. Separately, `tsc -b` in `packages/desktop` reported no errors for `Chat.tsx` because that file is not in the package's tsconfig; only `tsc -p renderer-next --noEmit` actually type-checks it.
- **Root Cause:** The dead-export gate scans `packages/*/src` only and counts cross-file imports inside that root; `renderer-next/src` sits outside it, so every renderer-consumed shell export is allowlisted by hand under the existing comment in `scripts/dead-exports-allow.txt`. The desktop tsconfig includes `src/**/*` and `test/**/*` but not the sibling `renderer-next/` directory, so a green desktop build says nothing about renderer source.
- **Rule:** When a new helper under `packages/desktop/src/shell` is consumed only by the renderer, add its `path|kind name` line to `scripts/dead-exports-allow.txt` under the "Consumed from packages/desktop/renderer-next/src" comment in the same PR, then run `bash scripts/check-dead-exports.sh`. Before claiming a renderer change type-checks, run `tsc -p packages/desktop/renderer-next --noEmit` as well: pre-existing `data.ts` TS2783 findings are expected, but no finding may name the file you touched.
