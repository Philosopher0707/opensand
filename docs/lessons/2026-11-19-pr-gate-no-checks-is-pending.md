# "No checks reported" is pending, not a red gate

- **Trap:** `scripts/pr-gate.sh --when-green` exited 1 on a PR that had just been pushed. `gh pr checks --watch` printed `no checks reported on the 'job/...' branch` and exited 1, and the gate reported a red CI with no failing job it could name, even though CI simply had not registered its checks yet.
- **Root Cause:** The gate only waited for a non-empty `statusCheckRollup` before starting the watch, then treated every non-zero watch exit as red. `gh pr checks` can still answer "no checks reported" after the rollup first appears, so the pending signal arrived as a failure and was classified as one.
- **Rule:** A `gh pr checks` failure whose output says "no checks reported" is pending. Retry it on the gate's normal poll backoff (`PR_GATE_POLL_SECONDS`, default 5 s), bounded by a 5-minute grace period or the `--timeout` deadline if that is sooner. When the grace runs out, exit 3 with `no CI checks appeared after <N>s for PR #<PR>`; only a real failing job exits 1. `scripts/pr-gate-selftest.sh` proves both paths: twice "no checks reported" then green merges, and checks that never appear give the bounded, named failure.
