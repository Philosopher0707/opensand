# A release install is not done until the installed app answers

- **Trap:** Process gap node 29: `scripts/release.sh --install` verified the installed version from `Info.plist`, then launched the binary with `--version >/dev/null 2>&1 || true`. A broken installed app could not fail the release: the command's exit status was discarded and no request was ever made to the running app.
- **Root Cause:** The install step checked on-disk metadata (plist version) rather than runtime behaviour. A launch that crashes or hangs, or a build whose local API does not respond, looked identical to a healthy install.
- **Rule:** After install, run `scripts/install-health-check.sh <app> <version>`: launch the installed bundle's own binary with a fresh isolated state dir and `OPENSAND_SMOKE=1`, wait for its published port and token, require `GET /api/diagnostics` to return 200 with the expected version, then kill exactly the launched PID and prove `~/.opensand` was untouched. `release.sh` fails with exit 2 when it does not pass. `scripts/install-health-check-selftest.sh` covers happy path, wrong version, no answer, early exit and missing bundle; the mutation probe proves the selftest goes red when the version check is broken. Never point this check at the real `/Applications/OpenSand.app` or `~/.opensand` during verification -- use a stub app in a temp install dir.
