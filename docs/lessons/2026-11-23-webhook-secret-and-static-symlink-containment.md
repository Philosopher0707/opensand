# Optional webhook secrets fail open and prefix checks leak through symlinks

**Trap:** F4: `WebhookGateway.handleWebhook` verified the signature only `if (webhook.secret)`, and `registerWebhook` accepted a missing or empty secret. A secret-less registration — including a legacy record loaded from `webhooks.json` — dispatched any caller's payload with no authentication. F7: the desktop static renderer contained paths with `resolvedPath.startsWith(path.resolve(this.rendererDir))`; a symlink inside `renderer/` pointing at a file or directory outside it, plus a sibling directory sharing the `renderer` prefix, both served outside bytes.

**Root Cause:** Both were happy-path checks. On an ingress path that has no session token, an optional credential is the same as no credential. A lexical string-prefix comparison says nothing about the inode the OS finally opens, so containment has to be decided after path resolution, not before.

**Rule:** (1) Require a non-empty secret at `registerWebhook` and fail closed at `handleWebhook` when a loaded registration has none; map that error to 400 in the desktop route handler. (2) Contain static files with `fs.realpathSync` on both the renderer root and the requested path, then `path.relative` (empty, not `..`, not absolute), and apply it again after the SPA fallback to `index.html`. Regression tests: `packages/coordinator/test/webhook-gateway.test.ts` F4 cases and `packages/desktop/test/static-renderer-containment.test.ts`. Mutation-checked green→red→green by reverting each source guard to HEAD: F4 failed 2 tests, F7 failed 4.
