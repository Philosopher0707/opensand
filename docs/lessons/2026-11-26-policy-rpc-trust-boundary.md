# Policy RPC: authenticate the caller, keep policy authority server-side, and validate every reply field

**Trap:** PR #273's policy daemon `validParams` checked only primitive types and forwarded `allowlistedHosts`, `approvalMode`, `tainted`, `sandboxed`, `workspaceRoot` and session identity from the RPC request straight into evaluation, so a raw-socket caller could grant itself `ALLOW` on `http://169.254.169.254/latest/meta-data/`. The client was just as trusting: a fake socket replying `{"result":{"action":"ALLOW"}}` with a matching id returned `ALLOW`. Error paths then copied `ENOENT` text with absolute paths into the RPC `reason`. A fourth finding was a spec mismatch: brief §4.1 auto-allows reads in `ask` mode while `autoAllows()` returns false for every mode but `auto_edit`/`auto`. My first red test also used a defaulted helper argument for the "missing token" case, so it passed a valid token and falsely reported ALLOW; a path that did not exist was silently tolerated by the canonicalizer, so it never triggered the error branch I meant to test.

**Root Cause:** Two boundaries were conflated. The wire request carried both untrusted call inputs (`toolName`, `args`) and trusted policy authority (approval mode, taint, sandbox, roots, allowlists, effect, identity); the reply was treated as trusted merely because its id matched. Neither end had a schema check for semantic consistency, and internal exception text was used as public output.

**Rule:** Authenticate every RPC caller with a daemon-owned shared secret (constant-time compare) and fail closed when it is absent or wrong. Put all policy authority in a daemon-owned context set at construction: the wire carries only tool name and args, and the server ignores injected context fields including `declaredEffect` and `strictEffects`. Validate the whole reply envelope and result: `jsonrpc === '2.0'`, matching id, complete `action`/`allowed`/`requiresApproval`/`reason`/`effect` and boolean/action consistency; anything else becomes `REQUIRE_APPROVAL`. Return stable public error strings and never echo exception text or absolute paths. Where the implementation and the brief disagree, implement the documented behaviour locally with a test (ask-mode reads) rather than changing shared code outside the PR's scope. In tests, avoid defaulted parameters for negative cases and choose a fixture that actually reaches the error branch. In a fresh worktree, build `@opensand/shared` and `@opensand/protocol` before the daemon suite. [checked: `packages/local-exec-daemon/test/policy-ipc-isolation.test.ts`]
