# ChatList rename: use the registered verb and update real-window click flows

**Trap:** The brief named `POST /api/sessions/:id/rename`, but the server registers `PATCH /api/sessions/:id`; coding from the brief would pass review and fail on click. Replacing `window.confirm` with inline confirmation left two real-window tests clicking delete once and stubbing `window.confirm`, so the row stayed behind. A new real-window rename test I added asserted `event-log.jsonl` on a legacy-seed folder the migration never wrote, and the extra Electron run hung past the tool timeout.
**Root Cause:** Briefs paraphrase routes and omit downstream fixtures; a UI interaction gaining a step changes how many clicks its real-window test must make. `check-dead-exports.sh` scans `packages/*/src` only, so exports consumed solely by `renderer-next` look dead.
**Rule:** Grep the server route registration and take the verb/path from code before writing a client call; when an interaction gains a step, update every test that drives that click and verify with the bounded runner rather than an unbounded direct run; list renderer-only exports in `scripts/dead-exports-allow.txt`. [checked: `sessionRenameRequest` unit test, `chatlist-actions.test.ts` source contract]
