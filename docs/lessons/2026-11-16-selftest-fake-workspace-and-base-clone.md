# A selftest's fake workspace must follow verify.sh, and worktrees need a stable base clone

- **Trap:** `scripts/verify-selftest.sh` failed on `main` (exit 127, `scripts/check-scripts-catalog.sh: No such file or directory`) after #102 made `verify.sh` call the catalog checker, and nobody noticed. Separately, every `worktree.sh new` needed a throwaway clone in `/tmp` to run from, because the script refused to run inside `~/dev/opensand`.
- **Root Cause:** The selftest copies only the files it knows `verify.sh` needs into a fake workspace, and nothing runs the selftests automatically (no CI step, no hook), so a new dependency of `verify.sh` broke it silently. Worktrees were created from whatever repository the caller happened to be in.
- **Rule:** When `verify.sh` calls a new script, add that script to `make_workspace` in `verify-selftest.sh` (a stub is enough when the script has its own selftest) and run the selftest. `scripts/worktree.sh base` keeps one reusable base clone (`~/dev/_scratch/opensand-base`, always clean, detached at `origin/main`); `new` hangs job worktrees off it, `done` and `prune` remove through the owning repository, and the base clone is never a removal target. Still owed: a CI or hook step that runs every `*-selftest.sh` (needs a `.github` change, which needs the owner's say-so).
