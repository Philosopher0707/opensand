# Allow owner-approved .github changes in pre-merge gate via explicit flag and label

**Trap:** PR #216 (F5 security-gates CI job, approved by the owner) was blocked from merging by `scripts/pr-gate.sh` Check 3 because changes under `.github/` were unconditionally forbidden with a hard failure. Adding an override flag alone would risk automated bots or contributors bypassing workflow protection without owner consent.
**Root Cause:** Workflow files in `.github/` define CI actions and security gates, so changes cannot be permitted silently or by default; however, legitimate owner-approved workflow updates need a supported merge path that preserves auditability.
**Rule:** `scripts/pr-gate.sh` accepts `--allow-github` modelled on `--allow-lockfile`. The flag requires that the PR carries the `owner-approved-github` label; without the label, the gate fails immediately explaining the requirement. When both the flag and the label are present, each allowed file under `.github/` is logged with a WARNING. Without the flag, the default failure for `.github/` diffs remains unchanged. Selftest cases in `scripts/pr-gate-selftest.sh` verify no flag -> fail, flag without label -> fail, and flag with label -> pass with warnings, backed by mutation probes. [checked: `scripts/pr-gate-selftest.sh`, `scripts/mutation-probe.sh`]
