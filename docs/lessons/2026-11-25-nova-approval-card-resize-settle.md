# Inline approval card: CI opened /welcome, so the chat panel was hidden

**Trap:** PR #247's `approvals-real-window.test.js` failed macOS CI repeatedly at `compact card visible` (runs 45559848181, 45560640165, 45563907787, 45565418247): the card was queryable, but its rect and `offsetWidth`/`offsetHeight` stayed zero for the full bounded 15 s wait, locally and on Linux it passed.

**Root Cause:** A fresh CI HOME has no API key and no Ollama, so `src/main.ts:183-184` loads `/welcome`; `parseViewFromLocation` then selects the welcome view and Shell adds `.hidden` to `#viewChat`, where the inline card lives. On the author's Mac Ollama is running locally, so onboarding was complete and the default view was chat. The test never navigated, so it measured a card inside a hidden panel; waiting on window width or the card's rect could not make a hidden element lay out.

**Rule:** A real-window test must navigate to the view it asserts on: call `navigateToView({ js, sleep }, "#chat", "#viewChat")` from `test/helpers/navigate-view.ts` before requesting or measuring an in-chat element. Direct `location.hash` assignment is forbidden by `scripts/check-real-window-nav.sh` because DOM presence does not prove the hashchange subscriber mounted. Do not infer the active view from a local environment where Ollama or a key is present. Measure a viewport the window already has before resizing, and keep the bounded wait on the measured element itself. [checked: `packages/desktop/test/approvals-real-window.test.ts`, `scripts/check-real-window-nav.sh`, `packages/desktop/src/main.ts`]
