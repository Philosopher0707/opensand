# A one-shot hash change loses the view switch, and a plain child kill leaves Electron descendants alive

**Trap:** `skills-real-window.test.js` intermittently stalled on `wait("...#viewSkills...visible")`; the file passed alone in 8 s. Separately, a real-window file killed at the 120 s ceiling left Electron helper processes running, and a selftest that only killed the direct child could not detect it.

**Root Cause:** Two distinct races. (1) The runner set `window.location.hash = '#skills'` once, as soon as `#skillsCardGrid` appeared; Preact installs the `hashchange` listener in a `useEffect` a tick later, so under load the event was lost and the view never switched. (2) `spawnSync`'s timeout sends the signal to the direct child only. Electron's helpers share the child's process group but not its PID, so they survive; the parent then waits on a test whose renderer is already gone.

**Rule:** In real-window runners, re-dispatch a hash/navigation event with a bounded retry until the target view is actually visible — a DOM node appearing is not proof that its subscription exists. Run every timed real-window child in its own process group (`spawn` with `detached: true`) and kill the group (`process.kill(-pid, 'SIGKILL')`) with a direct-child fallback; prove it with a selftest whose fake test leaves a sleeping grandchild. Resolve spawn promises on `exit`/`error` as well as `close`, because inherited stdio pipes can outlive Electron's main process.
