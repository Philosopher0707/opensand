# Step 4A policy fallback: mode-gate the legacy path, and make strict mode require a declared effect

**Trap:** PR #273's effect-first fail-closed evaluation removed the old "registered orchestrator tool" fallback unconditionally. Direct in-process callers (`LocalExecDaemon.evaluatePolicy` / `executeTool`) then classified `create_agent`, `list_agents`, `await_agent`, `show_app_access`, `slack_post_message`, `github_app_action` and `linear_create_issue` as `unknown` → `REQUIRE_APPROVAL`, so four coordinator tests failed with `permission_pending` on Node 22 CI. My first fix gated the fallback but still let strict mode infer `delegate` from `create_agent`'s name, so a missing `declaredEffect` still auto-allowed a registered tool over RPC.

**Root Cause:** Two different trust modes were collapsed into one evaluator. Legacy in-process callers have no declared effect and relied on name-based registration; the isolated RPC path must never trust a missing or unrecognised effect. Inference tables (`TOOL_EFFECTS`) include orchestrator tools, so leaving inference on in strict mode reopens the exact bypass the fallback gate closes.

**Rule:** Gate the legacy registered-tool fallback on `declaredEffect === undefined && !strictEffects`, and make strict mode resolve a missing/unrecognised declared effect to `unknown` (fail closed) without name inference. Force `strictEffects: true` on every RPC evaluation and ignore wire-level attempts to set it false; keep DENY rules, sensitive paths and egress denials unconditional in both modes. Test the exact tool that appears in the inference table, not only an unregistered tool. In a fresh scratch worktree, build all packages before the coordinator suite, and run long full-tree checks as a background job with a log when the harness caps foreground calls.
