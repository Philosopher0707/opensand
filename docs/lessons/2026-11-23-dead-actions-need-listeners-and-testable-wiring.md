# Dead desktop actions: distinguish the two IPC surfaces and keep wiring testable

- **Trap:** Four buttons looked dead for different reasons. The Settings action is a main-process `webContents.send('opensand:openSettings')`, while the Inspector rewind/compact actions are renderer-side DOM `CustomEvent`s. Assuming one bridge pattern for both would have added the wrong listener, and the "no backend action" fallback would have disabled buttons even though `/api/rollback` and `/api/compact` already existed in the desktop server.
- **Root Cause:** The renderer-next sources live outside the TypeScript test build (`packages/desktop/tsconfig.json` includes only `src/**/*` and `test/**/*`), so a test cannot import `renderer-next/src/data.ts` or the Preact components directly. Decisions about navigation, session guards and send arguments were embedded in those files with no unit-test seam.
- **Rule:** When wiring a dead action, first classify the event source (main→renderer IPC vs renderer DOM event) and check the desktop server routes before choosing the "Not available yet" fallback. Extract each decision into a pure `src/shell/*.ts` helper (`dead-actions-model.ts`, `query-send-model.ts`, `canRetryTurn`) so a fast unit test proves the red-then-green, and add one real-window test for the main-process IPC channel that unit tests cannot observe. Lessons go in `docs/lessons/` with the index regenerated, not at the end of `AGENTS_LEARNING.md`.
- **Trap 2:** `scripts/check-real-window-nav.sh` rejects any `location.hash =` text in a real-window test, and its regex also matches the first `=` of `location.hash === '#settings'`, so a read-only wait failed the gate.
- **Root Cause 2:** The guard is a plain grep for direct hash assignment, not a parser; it cannot distinguish assignment from strict equality.
- **Rule 2:** Spell hash reads as `String(window.location.hash) === '#settings'` in real-window runners, and reserve `navigateToView` for cases where the test itself must change the hash.
