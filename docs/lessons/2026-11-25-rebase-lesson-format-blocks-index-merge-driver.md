# Rebasing a PR that fixes lesson format: the index merge driver fails on the intermediate commit

- **Trap:** rebasing PR #243 onto `fe64b6b` resolved the three source conflicts (renderer `data.ts`, `shell.css`, `dead-exports-allow.txt`), then stopped on `docs/lessons/INDEX.md`. The merge driver printed `FAIL: 2026-11-25-gallery-stale-response-and-rebase-hurdles.md is missing a **Root Cause:** line`, although the branch's final commit fixes exactly that field. Separately, the first `worktree.sh new` attempt died on a transient `.git/config.lock` in the shared base clone and left a half-created branch behind.
- **Root Cause:** the generated index is rebuilt from the worktree's lesson files at the moment each commit is replayed; mid-rebase the lesson still had `**Cause:**` and the format-fixing commit had not been applied yet, so the driver refused to emit `%A`. The shared base clone is used by several bots at once, so a concurrent git config write can hold the lock; rerunning the same command verbatim would collide with the leftover branch.
- **Rule:** when a PR contains a lesson-format fix, pull that fix forward before continuing the rebase and regenerate `docs/lessons/INDEX.md` with `bash scripts/lessons-index.sh` — never hand-merge a generated index — then prove it with `bash scripts/lessons-index.sh --check` on the final head. Keep-both conflict resolution in shared barrels must leave exactly one `ShellData` type and one export block with every symbol imported. If `worktree.sh new` fails on a shared-base config lock, delete the leftover branch and retry once after inspecting state, never rerun unchanged. (OpenSand #243, 2026-11-25)
