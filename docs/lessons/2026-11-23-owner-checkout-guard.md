# Bots operating in the owner checkout refused by git common-dir guard

- **Trap:** Bots (Pixel, Nova, Dex) ran `scripts/worktree.sh`, `scripts/pr-gate.sh`, and `git fetch` against or inside the owner's development checkout `~/dev/opensand`, which holds the owner's local uncommitted work. Even with basic path checks, commands and worktrees hanging off the owner checkout shared the owner's `.git`, risking interference.
- **Root Cause:** Path assertions did not resolve the git common directory (`git rev-parse --path-format=absolute --git-common-dir`), allowing linked worktrees and indirect invocations to act against the owner's `.git`.
- **Rule:** `scripts/worktree.sh` and `scripts/pr-gate.sh` source `scripts/lib/owner-guard.sh` and resolve `--git-common-dir`. If it equals `$HOME/dev/opensand/.git` (or `OPENSAND_PROTECTED_CHECKOUT`), the scripts refuse with exit 4 ("<caller>: refusing to run from the owner's checkout; use ~/dev/_scratch/opensand-base"). Override only with `OPENSAND_OWNER=1`. `brief-row.sh` emits `cd ~/dev/_scratch/opensand-base && git fetch origin` as Scope line 1 and explicitly forbids running anything in `~/dev/opensand` in Fixed Rules. Tested hermetically by `scripts/owner-guard-selftest.sh` with mutation probes.
