# Job C: inline approval card — payload, hidden-window state and the global Escape shortcut

**Trap:** The chat reducer turned `approval_required` into `{ type: "approval" }`, discarding the `ToolApprovalRequest`, and the `approval` case also required a busy chat turn. A pending approval raised from another surface therefore never rendered a card. The real-window harness then stubbed `window.opensand.approveTool` to force the 409/timeout paths, but the rejection never reached the card, and Escape pressed in the composer closed the card as if the user had denied it.

**Root Cause:** Three independent causes: (1) the mapper and reducer dropped the payload and gated the card on `isChatBusy`, so an approval without an in-flight turn was invisible; (2) Electron's `contextBridge` API is frozen — assigning a function to `window.opensand.approveTool` from page JavaScript silently fails, so the failure-path stub was never used; (3) the shell's global Escape shortcut resolves to `cancel-turn` whenever a turn is busy, and `waiting` on an approval is busy, so Escape from anywhere stopped the turn and closed the card before the card's own handler ran.

**Rule:** Carry the full request through the mapper/reducer and render an approval card even with no in-flight turn; clear it once by `approvalId`. Expose a `__testApproveTool` override in the renderer data layer (matching the existing `__test*` hooks) instead of patching the frozen bridge; never patch a contextBridge method in a renderer test. Guard the shell's global Escape handler while an `.approval-card` is open so only the focused card denies. In hidden-window tests, allow a short settle delay after the card appears and poll async error state with ~300 ms gaps — rapid `executeJavaScript` polling can starve the render that shows a promise rejection. [checked: `packages/desktop/test/chat-turn-model.test.ts`, `packages/desktop/test/approvals-real-window.test.ts`]
