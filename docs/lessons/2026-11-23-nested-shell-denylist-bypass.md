# Wrapped commands bypassed the destructive-command denylist

**Trap:** Rigel's check of merged PR #203 ran 40 strings through the compiled `validateBashCommand`; 13 came back `isDangerous=false`: `sh -c "rm -rf /"`, `bash -c 'rm -rf /'`, `(rm -rf /)`, `$(rm -rf /)`, `` `rm -rf /` ``, `rm -rf "$HOME"`, `rm -rf "$X"`, `rm -rf ~/`, `rm -r -f /`, `rm --recursive --force /`, `r""m -rf /`, `rm -rf $(echo /)` and `rm -rf ""/`. Reproduced locally against the compiled validator before any edit.

**Root Cause:** `bash-validator.ts` was regex-only. The `rm` patterns ended in `(?:\s|$)`, so a closing `)`, backtick, `;` or `&` after the target stopped the match; flag detection assumed one combined `-rf`/`-fr` token; the target alternation had bare `/`, `/*` and `~` but not `~/`, quoted `$VAR` or `$(...)`; and the quote-stripping regex only handled `"/"`, `'/'` and `~` — not empty quotes inside a token (`r""m`) or quotes around a variable (`"$HOME"`). A denylist of shell spellings can never be complete, so hardening it alone would only move the bypass.

**Rule:** Two layers. (1) In `ipc-bridge.ts:requestUserApproval`, set `mustPrompt` for any `exec_command` whose text contains a nested shell or evaluation (`sh|bash|zsh|dash -c`, `eval`, `$(…)`, backticks, `| sh`/`| bash`, `base64 -d … |`, `source`/dot-file). This is a prompt in every mode, never a silent deny — the payload is assembled at runtime and the denylist cannot see it. (2) In `bash-validator.ts`, strip all quotes for matching, end patterns at `[\s;&|)"`]|$`, and match split/long flags, `~/`, quoted `$VAR` and `$(…)` targets. Tests: `packages/local-exec-daemon/test/bash-validator.test.ts` F3b tables and `packages/desktop/test/ipc-bridge.test.ts` F3b case, each mutation-checked green→red→green with `scripts/mutation-probe.sh`. Treat the denylist as defense-in-depth only; the OS sandbox remains the real boundary.
