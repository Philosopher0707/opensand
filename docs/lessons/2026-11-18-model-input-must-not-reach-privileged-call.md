# Model tool input must not be spread into a privileged call

- **Trap:** `exec_command` and `pty_spawn` built the runner call with `...input`, the raw tool-call arguments the model wrote. A model could then set `workspaceRoot` (write outside the turn's root), `customProfileString` (replace the generated sandbox profile), `allowNetwork: true` (open the network under a read-only turn), `homeDir` and `tempDir`, and `cwd` outside the workspace. The sandbox clamp covered only `sandboxProfile`, so every other field passed through.
- **Root Cause:** The privileged call was assembled by spreading the untrusted input and then overriding only the fields someone had remembered. The tool schema also advertised the containment fields to the model, so the widening was an offered option, not an accident. Nothing separated "fields the model may narrow" from "fields only the trusted turn context may set".
- **Rule:** Build a privileged call from explicit fields, or strip the containment fields from the input before any spread. The turn context is the only source of `workspaceRoot`; model input may only narrow the sandbox (`clampSandboxProfile`). Do not advertise containment fields in a model-facing schema. Each new containment field on a privileged call needs a regression test that a model-supplied value is ignored, and the test must run under a profile where the widening can actually be seen (a read-only turn cannot show a write to the temp dir).
