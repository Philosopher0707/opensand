# standing grants and turn aborts leave approval holes

- **Trap:** F2 let a standing "always allow" command be replayed with `unsandboxed: true` (or in a tainted session) with no prompt: `isStandingExecAllowed` matched on command text alone, and the coordinator skipped `onApprovalRequired` whenever the grant matched. The completeness audit found the mirror gap on `Stop`: aborting a turn mid-approval cancelled the signal but left the `activeApprovals` entry and its waiter pending forever.
- **Root Cause:** Two decisions were keyed on the wrong state. A standing grant is authority for one command under one sandbox/taint context, but the match key was only the command string; and turn cancellation only touched the abort controller, never the approval map or the promise it owns.
- **Rule:** Before a standing grant can satisfy an exec gate, pass the full context (`unsandboxed`, `tainted`) to the matcher and force a prompt when either is set — even when computer use is already allowed. Every path that aborts a turn (`cancelTurn`, `sendQuery` double-submit, session/clear-all deletion) must clear `activeApprovals` and resolve each waiter denied (`'prompt'` for folder trust). Never persist an `always` grant from an unsandboxed request. Mutation-check both guards: each test must fail when its guard is reverted.
