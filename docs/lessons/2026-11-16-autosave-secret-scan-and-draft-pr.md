# Automatic saving: secrets are refused, hooks stay on, the PR is a draft until it is ready

- **Trap:** Work in a job worktree lived only on disk until someone remembered to commit, push and open a PR, and a remembered `git add -A` could carry a `.env` or a token into the repository.
- **Root Cause:** Saving was a manual three-step ritual with no check on what it carried. The base clone is made with `git clone`, which does not copy hooks, so `.git/hooks/pre-commit` (build, test, blanket-add guard) is absent there and the worktrees hang off it: the earlier commits of this series ran no pre-commit hook. Installing the hook in the base clone would make every `save` run a full build and test, so it was left out on purpose and CI is the gate. A draft PR cannot be opened by `worktree.sh new`, because a branch with no commits has no PR and GitHub rejects it, so the draft opens on the first `save` push. `pr-gate.sh` read `state` only, so a draft passed check 1, the checkpoint tag was pushed, and only then did GitHub refuse the merge.
- **Rule:** Use `scripts/worktree.sh save "<message>"`: it stages by explicit path, scans the staged diff and refuses secret shapes (`sk-`, `ghp_`, `AKIA`, private key blocks, `.env` files except `.env.example`, `.env.sample`, `.env.template`) without printing the value, commits with hooks on (never `--no-verify`, never a `core.hooksPath` override), pushes without force and verifies the remote SHA, and opens a draft PR on the first push. `scripts/worktree.sh done` refuses unpushed commits. `pr-gate.sh` refuses a draft before it pushes the checkpoint tag; run `gh pr ready <N>` first. Selftests build fake secrets at runtime (a literal one can trip GitHub push protection) and write hooks and stubs without a shebang (an interpreter launch of a temp script stalled on macOS). Nothing runs `*-selftest.sh` automatically, so wiring them into CI (a `.github` change, which needs the owner's say-so) is still owed.
